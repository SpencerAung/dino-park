# E2E Playwright Setup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Install Playwright, add a 2-test back-navigation e2e suite, and wire a GitHub Actions workflow that runs on every push to `main`.

**Architecture:** Top-level `e2e/` directory organized by user journey, with its own `tsconfig.e2e.json` isolated from app type-check. Playwright spawns the production server (`next build && next start`) via its `webServer` config. CI runs Chromium only on push-to-main, caches browser binaries, uploads HTML report + traces on failure.

**Tech Stack:** Playwright (`@playwright/test` ^1.x), TypeScript, Next.js 16 (App Router), Node 20, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-06-06-e2e-playwright-setup-design.md`

**Working branch:** `chore-ci-e2e` (already created; the spec commit `7c624ba` is on it).

**Commit hygiene:** This working tree contains pre-existing unrelated dirt (`M public/demo/view-a.jpg`, `M public/demo/view-b.jpg`, untracked `.claude/`, `AGENTS.md`, `CLAUDE.md`, `CONTEXT.md`, `TECH-STACK.md`, other docs/ files, `public/demo/*-og.jpg`). For every commit, stage only the specific files named in the task — do NOT use `git add -A`, `git add .`, or `git commit -a`.

Open `tsconfig.json`. The current `exclude` is:

```json

```

Change it to:

```json

```

Leave all other fields unchanged.

- [ ] **Step 2: Create playwright.config.ts**

Create `playwright.config.ts` at the project root with this exact content:

```ts
import { defineConfig } from '@playwright/test'

export default defineConfig({
  testDir: './e2e',
  testMatch: '**/*.e2e.test.ts',
  fullyParallel: true,
  forbidOnly: !!process.env.CI,
  retries: process.env.CI ? 1 : 0,
  reporter: process.env.CI ? [['github'], ['html', { open: 'never' }]] : 'list',
  use: {
    baseURL: process.env.E2E_BASE_URL ?? 'http://localhost:3000',
    trace: 'on-first-retry',
    screenshot: 'only-on-failure',
  },
  projects: [{ name: 'chromium', use: { browserName: 'chromium' } }],
  webServer: {
    command: 'npm run build && npm run start',
    url: 'http://localhost:3000',
    reuseExistingServer: !process.env.CI,
    timeout: 120_000,

})
```

### Task 5: Write the back-navigation e2e test suite

**Files:**
- Create: `e2e/back-navigation.e2e.test.ts`

- [ ] **Step 1: Create the test file**

Create `e2e/back-navigation.e2e.test.ts` with this exact content:

```ts
import { test, expect } from '@playwright/test'

test.describe('back navigation', () => {
  test('round trip from root: view-a → view-b → back to view-a', async ({ page }) => {
    await page.goto('/p/demo')
    await expect(page).toHaveURL(/\/p\/demo\/view-a$/)

    await page.getByRole('button', { name: 'Go to view-b' }).click()
    await expect(page).toHaveURL(/\/p\/demo\/view-b$/)

    const backBtn = page.getByRole('button', { name: 'Back to view-a' })
    await expect(backBtn).toBeVisible()

    await backBtn.click()
    await expect(page).toHaveURL(/\/p\/demo\/view-a$/)

    await expect(page.getByRole('button', { name: /^Back to/ })).toHaveCount(0)
  })

  test('deep-link to view-b: back button works on fresh load', async ({ page }) => {
    await page.goto('/p/demo/view-b')
    const backBtn = page.getByRole('button', { name: 'Back to view-a' })
    await expect(backBtn).toBeVisible()

    await backBtn.click()
    await expect(page).toHaveURL(/\/p\/demo\/view-a$/)
  })
})
```

- [ ] **Step 2: Type-check the e2e file in isolation**

Run: `npx tsc --noEmit -p tsconfig.e2e.json`

Expected: Exits 0 with no output.

- [ ] **Step 3: Run the tests**

Run: `npm run test:e2e`

Expected: Playwright builds the Next.js app (~30s on first run), starts the server, runs both tests, both pass. Final output resembles:

```
Running 2 tests using 2 workers
  2 passed (Xs)
```

If tests fail because the dev server is already running on port 3000 from a separate terminal: stop the other server (Playwright's `webServer.reuseExistingServer` may attach but the prod build still expects a clean port). Or set `E2E_BASE_URL` to point at the already-running dev server and the build/start step is skipped.

If tests fail with an actual assertion error: this is the back-navigation feature being broken, not the test setup. Stop and report — don't paper over it.

### Task 6: Add the GitHub Actions workflow

**Files:**
- Create: `.github/workflows/e2e.yml`

- [ ] **Step 1: Create the workflow file**

Create `.github/workflows/e2e.yml` with this exact content:

```yaml
name: e2e

on:
  push:
    branches: [main]

concurrency:
  group: e2e-${{ github.ref }}
  cancel-in-progress: true

jobs:
  e2e:
    runs-on: ubuntu-latest
    timeout-minutes: 15
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm

      - run: npm ci

      - name: Cache Playwright browsers
        id: pw-cache
        uses: actions/cache@v4
        with:
          path: ~/.cache/ms-playwright
          key: pw-${{ runner.os }}-${{ hashFiles('package-lock.json') }}

      - name: Install Chromium
        if: steps.pw-cache.outputs.cache-hit != 'true'
        run: npx playwright install chromium --with-deps

      - name: Install Chromium system deps (cached binaries)
        if: steps.pw-cache.outputs.cache-hit == 'true'
        run: npx playwright install-deps chromium

      - run: npm run test:e2e

      - name: Upload Playwright report
        if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: playwright-report
          path: playwright-report/
          retention-days: 14

      - name: Upload traces
        if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: playwright-traces
          path: test-results/
          retention-days: 14
```

- [ ] **Step 2: Validate YAML structure**

Run: `python3 -c "import yaml; yaml.safe_load(open('.github/workflows/e2e.yml'))"`

Expected: No output, exits 0. (Confirms the YAML parses; doesn't validate against the GitHub Actions schema, but catches typos.)

If `python3` or `yaml` is unavailable, skip this step — GitHub will validate on push.

- [ ] **Step 3: Commit**

```bash

git commit -m "ci(e2e): run Playwright on push to main"
```

## Post-merge verification (NOT executed as a task)

These criteria from the spec require infrastructure that doesn't exist until after the PR is merged. They are tracked here so a follow-up confirms the gate works end-to-end:

- A push to `main` (the merge commit) triggers `.github/workflows/e2e.yml` and the job goes green end-to-end.
- A deliberately-failing change (e.g., rename `aria-label="Back to view-a"` → `"Return"` on a follow-up branch and merge it as a test, then revert) produces an HTML report + trace artifact uploaded to the failed run.

These two checks happen against `main` after merge — the executing agent cannot perform them inline.
